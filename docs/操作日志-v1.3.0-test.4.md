# v1.3.0-test.4 操作日志 · 广告过滤

日期：2026-11-24
基线：v1.3.0-test.3（versionCode 7）→ v1.3.0-test.4（versionCode 8）
范围：手机端（arm64-v8a）+ 电视端（armeabi-v7a），两端共用同一套实现

## 一、需求

App 播放剧集时会被源站的片头广告、中插广告打断，希望在播放环节把这些广告跳过去。

## 二、为什么用「清洗播放列表」而不是「拦截请求」

App 的播放器是 expo-av（底层 ExoPlayer），它在原生层直接向 CDN 拉分片，
JS 层没有 hook 能拦到这些请求。因此采用「先改播放列表、再交给播放器」的方式：

1. 播放前把 m3u8 拉下来（带 2.5s 预算）；
2. 按规则删掉广告分片，把所有相对地址改成绝对地址；
3. 写到 App 缓存目录 `…/cache/adblock/xxx.m3u8`，把 `file://` 地址交给播放器。

广告分片不在播放列表里，播放器根本不会去请求，属于真跳过。
代价是加密源必须保留 `#EXT-X-KEY`、分片地址必须绝对化，这两点都已处理。

## 三、识别规则

| 规则 | 依据 | 保护 |
|---|---|---|
| SCTE-35 广告段 | `#EXT-X-CUE-OUT` / `CUE-OUT-CONT` 到 `#EXT-X-CUE-IN` 之间的分片 | 疑似广告 > 总时长 30% 或 > 5 分钟视为内容分段，不删 |
| 片头贴片 | 开头 1~3 段来自「正片从不使用的域名」，累计 ≤ 2 分钟 | 出现次数与位置双重判定，整片同 CDN 不会误删 |
| 广告域名/路径 | doubleclick、googlesyndication、imasdk、preroll、midroll、sponsor 等 | 关键字命中超过三成时整条规则作废 |
| 全线兜底 | 删完为 0 段 | 放弃清洗，原样播放 |

## 四、兜底（去广告不能影响能看）

- 直播型 m3u8（无 `#EXT-X-ENDLIST`）不落地，直接透传，避免滚动列表被冻住；
- 2.5 秒内没清洗完，先播原始地址，结果不再回切（不会二次加载）；
- 本地列表播放报错，立即回退原始地址，并把该域名本次运行内拉黑；
- 删除开头分片时修正 `#EXT-X-MEDIA-SEQUENCE`，避免部分播放器判定序列倒退；
- 被删分片里的 `#EXT-X-KEY` / `#EXT-X-MAP` 顺延到下一段，加密源不会解密失败。
