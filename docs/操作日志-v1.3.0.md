## 二、远程更新（本次重点）

### 2.1 链路

```
App 启动 / 设置页点「检查更新」
      ↓
拉 version.json（GitHub 直连 → ghfast → jsDelivr 依次回退）
      ↓
按设备取渠道：Platform.isTV → tv（armeabi-v7a），否则 phone（arm64-v8a）
      ↓
与本机 package.json 的 version 比较，远端更大 → 弹窗
      ↓
下载 APK（失败自动切镜像）→ expo-file-system 落盘 → IntentLauncher 拉起系统安装器
```

### 2.2 本次改动

- `app/_layout.tsx`：挂回 `<UpdateModal />`，启动页结束后延后 3 秒静默检查；
  12 小时内不重复检查（`UPDATE_CONFIG.CHECK_INTERVAL`），跳过过的版本不再弹窗。
- `app/settings.tsx`：设置页恢复「远程更新」区块（仅 Android），可手动检查、看更新说明、直接更新。
- `version.json`：正式清单，指向 `v1.3.0` 的 tv / phone 两个 Release 资源，附带两个镜像地址。
- `services/updateService.ts`：修复版本比较。

### 2.3 修掉的一个隐藏坑

`compareVersions` 原来是 `split('.').map(Number)`：

```
'1.3.0-test.6'.split('.')  →  ['1', '3', '0-test', '6']  →  [1, 3, NaN, 6]
```

一旦遇到 `NaN`，`>` 和 `<` 都返回 false，比较直接退化成「不相等也不算更大」。
实测后果是：装测试版的用户判断「1.3.0 是否比 1.3.0-test.6 新」时返回 `-1`，
**永远收不到正式版更新**。

现在先按 `[-+]` 截断预发布后缀再比较，`1.3.0` 与 `1.3.0-test.6` 都归一化为 `[1,3,0]`，
再按 `versionCode` 的先后由远端清单决定（正式版 11 > 测试版 10），可以正常收到推送。

## 五、已知限制

- 远程更新只覆盖「整包替换」，没有增量包；下载 21~26 MB，弱网下耗时较长。
- 安装需要系统「允许未知来源安装」权限，首次会弹系统授权页。
- 电视盒子普遍无法识别 `Platform.isTV`，渠道判定在部分机型上可能落到 `phone`；
  这类机型若装的是 32 位包，更新时会下到 64 位包导致安装失败，需要手动从 Release 取 32 位包。
  后续可考虑读取 `Build.SUPPORTED_ABIS` 来判定渠道。

## 六、回滚方式

1. 把仓库根目录 `version.json` 的 `version` 与两个渠道的 `version` / `url` 改回目标版本；
2. 或直接把 `version.json` 的 `version` 调低，客户端即视为「已是最新」，不再提示。
3. 安装包回滚需手动装旧版 Release（versionCode 更低，覆盖安装会被系统拒绝，需先卸载）。
