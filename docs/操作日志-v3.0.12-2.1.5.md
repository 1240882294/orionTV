## 二、现象与根因

### 2.1 电视端联想搜索

用户补充的关键信息改变了结论：

> 用系统输入法打中文能搜到；点联想词搜不到；但**先用系统输入法搜过一次之后，再点同一个联想词就能搜到**。

「顺序依赖」说明不是词库问题，也不是网络整体不可用 —— 是**首个请求被挤掉**。

| 环节 | 事实 |
|---|---|
| 词库匹配 | 正常。结果页标题显示 `「仙逆」`，说明联想词已命中并正确传参 |
| 请求 | `api.searchVideos` → `/api/search`（服务端聚合所有源） |
| 超时 | 默认 `DEFAULT_TIMEOUT_MS = 8000`，**无重试** |
| 抢占源 | 搜索页挂载即 `ensureSuggestIndex` → `fetchDoubanSeeds` **10 个并发** `/api/douban` |
| 现场带宽 | 截图右下角 `↓253 B/s` |

链路：`开页面 → 10 个并发榜单请求占满带宽 → 点联想词 → 第 11 个请求排队 → 8 秒等不到首包 → catch → 「搜索失败」`。

第二次能成功，是因为第一次已经把 DNS/TCP/TLS 建成、连接变热，且榜单请求此时已结束 —— 所以「用过一次就好了」。

**与上一轮改动无关**：`app/search.tsx`、`services/api.ts` 本轮之前一行未动。

### 2.2 手机端起播即暂停、点播放报错

「操作失败」全项目唯一出处：

```ts
// stores/playerStore.ts  togglePlayPause
await videoRef?.current?.playAsync();   // 抛错 → Toast「操作失败」
```

`playAsync` 抛的是 expo-av 的 `Cannot complete operation because the Video component has not yet loaded`。也就是说：**代码手里那个 Video 实例还没加载完，但 store 认为它已经加载好了。**

两个条件叠在一起才出现：

| # | 机制 | 后果 |
|---|---|---|
| 1 | `useAdFreePlayback` 首帧给 `url: rawUrl`，effect 立刻又清成 `undefined` | `<Video>` 先挂载一次 → 被卸载 → 重新挂载 |
| 2 | 重挂载后 `playerStore.status` 仍属旧实例（`isLoaded=true / isPlaying=false`） | 控件显示「暂停」（假象）；点播放打到新实例 → 报「操作失败」 |
| 3 | `onLoad` 里 `await setPositionAsync(954000)` 在 `await playAsync()` 之前 | HLS seek 要现拉第 15 分钟的分片，弱网下卡住/抛错，**播放指令从未发出** |

第 3 条解释了「画面出来了却是暂停」：`shouldPlay: true` 让首帧渲染出来了，但 seek 之后的播放状态被重置，而补播那句在 try 里排在 seek 后面，没机会执行。

第 1、2 条是老代码；第 3 条的触发概率被上一轮「等全量线路后再 loadVideo」放大 —— 时序更靠后，正好和去广告的「清空→重挂」撞在同一段弱网窗口里。**是放大，不是新引入。**

## 三、代码改动

| 文件 | 改动 |
|---|---|
| `services/api.ts` | 新增 `SEARCH_TIMEOUT_MS = 12000`、`SEARCH_RETRY_TIMEOUT_MS = 10000`；`searchVideos` 仅对 `timeout` 重试一次（network / 401 / 5xx 不重试） |
| `services/searchSuggestIndex.ts` | `fetchDoubanSeeds` 改分批，`DOUBAN_CONCURRENCY = 2`；`loadRemoteSeeds` 先等 `REMOTE_SEED_DELAY_MS = 3000` 再拉，把首搜窗口让出来；导出 `fetchDoubanSeeds` 供测试 |
| `app/search.tsx` | 区分超时与接口错误文案；新增 `[SEARCH] "词" hit N in Xms` / `failed after Xms` 日志 |
| `hooks/useVideoHandlers.ts` | `onLoad` 改为**先 play 再 seek**；seek 带 5000ms 宽容度；seek 后再补一枪 `playAsync`；seek 失败不阻断播放 |
| `hooks/useAdFreePlayback.ts` | `useState` 初始化时判断「需要清洗」→ 直接进 `resolving`，播放器只挂一次 |
| `app/play.tsx` | 新增 `useEffect([playUrl])`：`setState({ status: null, isLoading: true })` |
| `stores/playerStore.ts` | `togglePlayPause`：`!status.isLoaded` 时提示「正在加载，请稍候」；`not yet loaded` 不再报「操作失败」 |
