## 一、本轮需求

1. 电视端右侧「热门搜索」右边加「最近搜索」；
2. 联想搜索感觉特别慢，先讲清运行逻辑再决定怎么改；
3. 打开搜索只调本地词库，不被后台请求抢带宽；
4. 抢带宽导致搜不到时自动重试 2、3 次，仍失败则提示网络问题；
5. 失败提示里加「重新搜索」，且返回后**不用重新输入**关键词。

## 二、改动前的运行逻辑（核查结论）

| 阶段 | 实际行为 |
|---|---|
| 打开搜索页 | 灌 6908 条内置词库（600/批，24ms 间隔）+ 读本地历史/收藏/记录；**3 秒后**后台拉 10 个豆瓣榜单（并发 2）。**不发 `/api/search`** |
| 空输入 | `hotTitles(6)` 取内存词库前 6 条 → 「热门搜索」。因豆瓣条目 `updatedAt` 最新，会整批顶到前面，所以每次看到的 6 条会变 |
| 按字母 | `suggestTitles` → `rankSuggestions`，纯本地匹配（首字母/全拼前缀、中文包含），**零网络** |
| 点联想词 | `api.searchVideos` → `/api/search`（服务端聚合），原为 12s 超时 + 重试 1 次 |
| 失败 | 错误页有「重新搜索」，但内部 `setKeyword("")`，返回后关键词被清空 |

性能基准（桌面 CPU，临时用例赛后删除）：6908 条建索引 58ms（8.4µs/条）；
7000 条全表匹配单次 0.30ms。按低端电视 5~10 倍估算，本地联想仍在毫秒级，
**慢在服务端聚合搜索与后台榜单抢带宽**，不在词库。

## 三、改动

| 文件 | 改动 |
|---|---|
| `services/searchSuggestIndex.ts` | ① `ensureSuggestIndex(force, onProgress, { remote })`，默认 `remote=false`，搜索页不再拉豆瓣；② 新增 `warmRemoteSeeds()`，首搜成功后补一次，模块内幂等；③ `hotTitles` 排序改为「权重 → 内置种子优先 → 更新时间」 |
| `services/api.ts` | `searchVideos(query, options)`：单次 8s、最多 3 次尝试、退避 [0, 400, 1200]，只对 `timeout` 重试，`onAttempt(n,total)` 供界面提示；`SearchOptions` 可被调用方覆盖 |
| `app/search.tsx` | ① 错误页加「重试一次」按钮（`handleSearch(searchTerm)` 原地重搜，TV 上 `hasTVPreferredFocus`）；② `handleBackToKeyboard` / 返回键改为 `setKeyword(searchTerm)`，保留关键词；③ loading 时显示「网络较慢，正在第 n/3 次尝试…」；④ 电视端空输入时右列拆成「热门搜索 / 最近搜索」两列，各 6 条；⑤ `handleSearch` 发起时写搜索历史并刷新最近列表；⑥ 首搜成功后 `warmRemoteSeeds()` |
| `services/storage.ts` | `SearchHistoryManager`：新增 `getLocal/setLocal`；`add` 两种模式都写本地（20 条、去重前置）；`get` 服务端取不到时回退本地 |
| `stores/detailStore.ts` | 降级搜索 `attempts: 2`、后台补全 `attempts: 1`，避免详情页被重试拖长 |

## 七、已知取舍

- 豆瓣榜单不再在打开搜索页时拉取，**内置 6908 条之外的新剧**要等首搜成功后才补进词库；
- 3 次尝试在极弱网下最多等约 26 秒（8 + 0.4 + 8 + 1.2 + 8），期间有「第 n/3 次」提示；如果实机觉得太久，可把 `attempts` 调到 2（约 17 秒）。
