# 操作日志 · 电视端 3.0.14-test.1（搜索结果按剧折叠）

> 日期：2026-11-28 21:20–21:40
> 需求：搜索结果里同一部剧的多个源只显示一张卡，角标显示总集数；标题为主、年份兜底；只动电视端
> 上一版：电视 `3.0.13-test.1`（3020）；手机停在 `2.1.5-test.1`（2116），本批不动

## 一、为什么改

搜「愚者之夜」返回 189 条，实际是同一部剧 × 9 个源。服务端 `/api/search` 逐源返回，
搜索页直接平铺，所以出现 9 张一模一样的卡。

关键证据（决定了改动风险很低）：

1. `stores/detailStore.ts` 的 `processAndSetResults` 本来就按 `source` 合并，
   `sources` 里保留每个源的 `source/id/episodes` —— 详情页的线路列表就是这么来的；
2. `components/VideoCard.tv.tsx` 点卡片只传 `{ source, q: title }`，**不传 `id`**；
3. `detailStore.init` 走单源快路径的条件是 `if (preferredSource && id)`，缺 `id` 就不会进，
   直接走 `else` 分支：`getResources()` → 每个源并发 `searchVideo(q)` → 逐个合并。

所以点第 3 张「愚者之夜」进详情，看到的也是全部 9 条线路。搜索页的重复卡是纯冗余，
折叠不会丢任何一条线路。

## 二、改了什么

| 文件 | 改动 |
|---|---|
| `services/searchGrouping.ts`（新增） | `normalizeTitle` / `groupByTitle` 纯函数，输出 `GroupedResult[]`（含 `sources`、`totalEpisodes`） |
| `app/search.tsx` | `groupedResults = useMemo(() => isTV ? groupByTitle(results) : [], …)`；电视列表改喂分组数据；标题栏改「x 部 · 共 y 条线路」 |
| `components/VideoCard.tv.tsx` | 角标：`totalEpisodes > 0` 显示「共 N 集」，否则回退源名 |
| `services/__tests__/searchGrouping.test.ts`（新增） | 9 条：合并、拆分、年份兜底、括号归一化、全角、集数取最大、顺序、空值 |
| `services/__tests__/searchTimeout.test.ts` | 顺手修掉上一轮遗留的 `mockImplementation` 类型报错（`as any`） |

分组规则：

- 归一化：全角转半角 → 去 `()/（）/[]/【】` 标注 → 压缩空白与 `·-—` → 小写；
- 同组：归一化标题相同，且年份不冲突；
- 年份：两边都有且不同 → 拆开；任一方为空 → 合并；
- 集数：组内最大 `episodes.length`；
- 顺序：保持服务端顺序。

## 六、已知取舍

- 标题写法差异大的源仍会单独成卡 —— 少合并只是多一张卡，不影响播放；
- 集数取组内最大值，某个源更新更快时其它源可能少几集，进详情页能看到每个源的实际集数；
- 年份缺失的源会并入第一个同年/无年的组，极少数同名不同版可能仍被合并（进详情页能看到源名区分）。
