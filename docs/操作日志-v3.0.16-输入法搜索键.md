# 操作日志 · 电视 3.0.16-test.1（输入法搜索键失效）

> 日期：2026-11-28 22:37–23:25
> 现象：搜索页用系统输入法打中文，点输入法的「搜索」键，有时正常搜索，有时键盘收起、退回字母键盘页，什么都没搜
> 基线：`4285a52`（双端转正后的 HEAD）

## 一、定位过程

先看弹窗实现（`app/search.tsx` 的 `SystemInputModal`）：

```tsx
const submit = () => {
  const text = draftRef.current.trim();
  if (text) onSubmit(text);   // 空文本 = 什么都不做
};

<TextInput onSubmitEditing={submit} ... />
```

只有 `onSubmitEditing` 一个入口。这个回调在 Android 上由 `ReactEditText` 的
`onEditorAction` 触发，**前提是输入法发送 `IME_ACTION_SEARCH`**。

电视输入法不是同一套实现（用户截图里是系统「拼音全键」，底部还有拼音九键 / 笔画键盘 / 搜索键）：

| 输入法行为 | RN 回调 | 结果 |
|---|---|---|
| 发 EditorAction(SEARCH) | `onSubmitEditing` | 正常搜索 |
| 只发 Enter keyevent | 无（RN 不把 keyevent 转成 submit） | 不搜 |
| 只关闭键盘窗口 | 无 | 不搜 |

三种行为在不同输入法、不同输入法版本、甚至有没有候选词上屏时都可能不同，所以表现为「时好时坏」。

再往下看，有两个地方把小毛病放大成「看起来毫无反应」：

1. **空文本静默 return** —— 不搜、不提示、不关窗。用户点完什么反馈都没有；
2. **打开弹窗时 90 / 420 / 900 ms 各清空一次输入框**：

   ```tsx
   const timers = [90, 420, 900].map((delay) =>
     setTimeout(() => { inputRef.current?.setNativeProps?.({ text: "" }); ... }, delay)
   );
   ```

   手快的人在 900 ms 内已经把字打进去了，第三次 `setNativeProps` 会把**已输入的字抹掉**，
   并触发 `onChangeText("")` 把 `draftRef` 一起清空 —— 再按搜索键就是一次空提交。

还有一个体验问题：提交后是裸 `setSystemInputVisible(false)`，没走 `closeSystemInput`，
电视上 Dialog 一销毁焦点就没主了，整页没有高亮，看起来像"退回了某个界面"。

## 二、改了什么

只改 `app/search.tsx`，不动其它逻辑。

| 改动 | 原因 |
|---|---|
| `onSubmitEditing` + `onKeyPress`(Enter) + `onBlur` / `onEndEditing` 三路提交 | 覆盖三种输入法行为；输入法只关窗口时，有字就自动搜 |
| `submittedRef` 幂等 | 三条路可能同时到（Enter 常伴随 blur），只认第一次 |
| `cancelledRef` | 点 X / 返回键是取消，blur 兜底不能把它变成"顺手搜一下" |
| 空提交显示弹窗内红字 | 不再静默；Modal 是独立窗口会盖住 Toast，所以不用 Toast |
| 清空改成「仅当输入框仍为空」+ 只清 80/380 ms 两次 | 不抹掉用户刚打的字 |
| 提交后走 `closeSystemInput` | 焦点回到键盘图标，避免整页无高亮 |
| 提示文案改「按输入法的『搜索』键或下面的按钮」 | 用户不知道还能点弹窗里的按钮 |
