# 操作日志 · 双端 3.0.15 / 2.1.6 转正

> 日期：2026-11-28 22:32–23:10
> 需求：把电视 `3.0.15-test.1`、手机 `2.1.6-test.1` 两个测试版一起升为正式版，并更新 GitHub 主页
> 基线：`c3899e3`（打这两个测试包时的代码，当前 HEAD）

## 一、为什么必须重新编译

`BUILD_VERSION` 在打包时写进 `constants/BuildInfo.ts`，运行期 `IS_TEST_BUILD = /-test(\.|$)/.test(BUILD_VERSION)`
决定读 `version-test.json` 还是 `version.json`。只把 APK 改个文件名、或只改清单，装完仍是测试包：

- 设置页继续显示 `3.0.15-test.1`；
- 继续读测试清单，正式通道的推送永远收不到。

所以两端都按正式版号重新出包。

## 二、versionCode 为什么各加 1

| 端 | 测试版 | 正式版 | 说明 |
|---|---|---|---|
| 电视 | `3.0.15-test.1` / 3022 | **`3.0.15` / 3023** | 已装测试包的电视能覆盖升级 |
| 手机 | `2.1.6-test.1` / 2119 | **`2.1.6` / 2120** | 同上 |

沿用 README 里的规则「正式版 versionCode 必须大于在测的测试包」，不能用同号：
部分电视盒子与国产 ROM 的安装器会把同 versionCode 判成「已安装相同版本」而拒绝安装。

## 三、构建

| 步骤 | 电视 | 手机 |
|---|---|---|
| `ORION_CHANNEL` | `tv` | `phone` |
| `apply-build-info` | `3.0.15` / 3023 | `2.1.6` / 2120 |
| `set-abi.js` | `armeabi-v7a` | `arm64-v8a` |
| 耗时 | 5m50s | 7m17s |
| `.so` 数量 | 48 | 48 |

**第一次电视构建失败**：`Gradle build daemon disappeared unexpectedly`。
容器 cgroup 上限仍是 8 GiB，上次构建残留的两个 Kotlin daemon（各 `-Xmx4096m`）加上
Gradle 自身把内存顶爆。处理：

```sh
pkill -f "KotlinCompileDaemon"; pkill -f "[G]radleDaemon"; pkill -f "[e]xport:embed"
# 内存从 4.08 GB 降到 1.38 GB 后重跑
```

随后统一改成保守参数，两端一次通过：

```sh
./gradlew assembleRelease --no-daemon --max-workers=2 \
  -Dorg.gradle.jvmargs="-Xmx2560m -XX:MaxMetaspaceSize=512m" \
  -Pkotlin.compiler.execution.strategy=in-process
# CMAKE_BUILD_PARALLEL_LEVEL=1、NODE_OPTIONS=--max-old-space-size=1536
```
