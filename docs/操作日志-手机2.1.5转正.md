# 操作日志 · 手机端 2.1.5 转正

> 日期：2026-11-28 21:42–21:55
> 需求：把手机端 `2.1.5-test.1` 推送为正式版；电视端暂时不动
> 基线：`b579dad`（打 2.1.5 测试包时的代码），**不是**当前 HEAD

## 一、为什么从 b579dad 重新构建

当前 HEAD（`e97b6b4`）比 2.1.5 多了两批改动：

1. `4c2f641` 搜索页不抢带宽 / 失败重试 3 次 / 最近搜索 —— 这是 2.1.6 带的内容，手机端不需要；
2. `e97b6b4` 搜索结果折叠 —— 只在电视端生效，但代码是共用的。

用户要求「手机端不要动」，所以切到 `b579dad`（2.1.5 测试包对应的提交）重新出包，
而不是简单把 `2.1.5-test.1` 的 APK 改个名 —— APK 里的 `BUILD_VERSION` 是固化的，
`2.1.5-test.1` 会被判成测试包（`IS_TEST_BUILD = true`），装完仍读 `version-test.json`，
等于没转正。

## 二、做了什么

| 步骤 | 结果 |
|---|---|
| `git checkout b579dad` | 分离头指针，代码回到 2.1.5 |
| `apply-build-info` | `BUILD_CHANNEL=phone`、`BUILD_VERSION=2.1.5`、`CODE=2118` |
| `build.gradle` | `versionCode 2118` / `versionName "2.1.5"` |
| `set-abi.js phone` | `arm64-v8a` |
| 构建 | armeabi 无、arm64 48 个 `.so`，3m07s |
| `git checkout -f main` | 恢复工作区到最新代码 |

**第一次构建失败**：`Gradle build daemon disappeared`。原因是上一次 TV 构建残留的
`expo export:embed` 进程占着 1 GB 内存（容器 8 GiB，当时已用 5.5 GB）。清掉残留进程后重试成功。

## 三、版本号取 2118

| 版本 | versionCode | 状态 |
|---|---|---|
| `2.1.3` | 2114 | 上一正式版 |
| `2.1.5-test.1` | 2116 | 测试版，已装机的会收到本次转正 |
| `2.1.6-test.1` | 2117 | 已撤回，少数机器可能装着 |
| **`2.1.5`** | **2118** | 本次正式版 |

取 2118 而不是 2116/2117：保证 versionCode 严格大于所有已发出的包，装过测试版的机器
都能直接覆盖安装，不会被安装器判定为「同版本」而卡住。

## 七、注意事项

1. **装过 `2.1.6-test.1` 的机器不会收到提示**：它版本号更高（2.1.6 > 2.1.5），
   `compareVersions` 判定无需更新；该版本只存在约 20 分钟，且功能与 2.1.5 一致，影响可忽略。
   需要的话可以手动装 2.1.5（versionCode 2118 更大，能覆盖）。
2. **`2.1.5-test.1` 的 Release 保留**，只是不再被任何清单指向；泄漏风险为零（版本号更低）。
3. 电视端完全未动：包、Release、清单 tv 字段都没变。
